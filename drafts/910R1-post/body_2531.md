感谢复核。分两部分：版本号澄清，以及按你们要求在 CANN 9.1.0 上的实测结果。

### 1. `triton-ascend 3.5.0` 不是笔误，而是 `triton.__version__` 的输出值

我们环境里的 pip 包是 `triton-ascend 3.6.0+git0cfb1708`（wheel 名 `triton_ascend-3.6.0+git0cfb1708-cp312-cp312-linux_aarch64.whl`），
而 issue 里写的 `3.5.0` 取自 `import triton; print(triton.__version__)`。
这两个值在你们仓库里本来就不一致：commit `0cfb1708` 的 `version.txt` 是 `3.6.0`，
而 `python/triton/__init__.py` 里写的是 `__version__ = '3.5.0'`。
所以「TA 3.6.0 只兼容 CANN 9.1.0」这个约束和我们的环境是对得上的——我们跑的就是 TA 3.6.0。
这个写法造成了误会，抱歉；我们后续一律写 pip 包版本。

### 2. 在 CANN 9.1.0 上复跑：复现

自包含脚本（只依赖 torch + torch_npu + 标准库，**不依赖 pytest、不依赖任何测试树**）。
两臂**只换 `source /opt/ascend/cann-*/set_env.sh` 那一行**，其余完全相同：

| 项 | 值 |
|---|---|
| 设备 | Ascend910B4（issue 正文原报的是 910B2）· Python 3.12.13 |
| torch | 2.15.0.dev20260917+cpu |
| torch_npu | 2.15.0.dev20260917+gitec69335 (ec693356f4) |
| triton-ascend | pip `3.6.0+git0cfb1708`（`triton.__version__` = 3.5.0） |
| 后端 | `TORCHINDUCTOR_NPU_BACKEND=triton_experimental` |
| 臂 A | CANN 9.1.0（`ASCEND_HOME_PATH=/opt/ascend/cann-9.1.0`） |
| 臂 B | CANN 9.2.0-beta.2（对照） |

用例：`size=96, nh=4, head_dim=32, seed=0`，fp16 与 bf16 各一；
`F.scaled_dot_product_attention` + 上三角 `-inf` attn_mask，eager 与 `torch.compile` 对比。
另用 **fp32 CPU eager 作为真值**判定到底哪一侧错（张量共 12288 个元素）。

| dtype | 臂 | eager vs fp32 超标 | compiled vs fp32 超标 | eager vs fp32 maxdiff | compiled vs fp32 maxdiff | eager vs compiled maxdiff |
|---|---|---|---|---|---|---|
| fp16 | **CANN 9.1.0** | **0/12288** | **11674/12288** | 0.000389 | **0.619038** | 0.618896 |
| bf16 | **CANN 9.1.0** | 1379/12288 | 11193/12288 | 0.002946 | **0.604969** | 0.605469 |
| fp16 | CANN 9.2.0-beta.2 | 0/12288 | 9936/12288 | 0.000389 | 0.073104 | 0.073242 |
| bf16 | CANN 9.2.0-beta.2 | 1379/12288 | 9992/12288 | 0.002946 | 0.073104 | 0.074219 |

（超标 = 超过 `rtol=atol=1e-3`；bf16 那 1379/12288 是 bf16 自身的舍入，
eager vs fp32 maxdiff 仅 0.0029。）

### 3. 结论

1. 在 **CANN 9.1.0 + TA 3.6.0 上同样复现**，不是只在 9.2.0 场景才有。
2. fp32 真值表明**错的是 compiled 分支**：fp16 eager 与 fp32 完全一致（0/12288），
   而 compiled 偏差达 0.619 ⇒ 不是 eager 的问题，也不是半精度精度问题。
3. CANN 9.1.0 上的偏差比 9.2.0-beta.2 **大约 8 倍**（0.619 vs 0.073）。

### 4. 关于「mainline + CANN 9.1.0 未出现该问题」

我们的 TA 是 `0cfb1708`（该 commit 日期 2026-08-05），与你们当前 mainline 之间可能存在差异。
**用下面这段脚本在你们 mainline + CANN 9.1.0 上跑一次**，应该能立刻看出分歧点在哪；
如果你们那边是 0/12288，那说明差异是在那之后修掉的，也麻烦告知对应的 commit。

<details><summary>复现脚本（自包含，保存为 repro_2531.py）</summary>

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Self-contained reproduction for triton-ascend issue #2531
=========================================================
"F.scaled_dot_product_attention(q, k, v, attn_mask=causal_mask) gives WRONG VALUES
 under torch.compile with the NPU triton_experimental backend."

Dependencies: torch + torch_npu + Python stdlib ONLY.
No pytest, no torch_npu/dynamo test framework, no `_npu` patched test file.

Usage (inside the NPU container, after sourcing the desired CANN env):

    source /opt/ascend/cann-9.1.0/set_env.sh          # or .../cann-9.2.0-beta.2/set_env.sh
    export TORCHINDUCTOR_NPU_BACKEND=triton_experimental
    /opt/miniconda/envs/npu/bin/python repro_2531.py

What it does
------------
For dtype in (float16, bfloat16):
  * build q, k, v of shape (1, nh=4, size=96, head_dim=32) on the NPU
  * build an explicit additive causal mask of the same dtype (0 / -inf)
  * run eager  F.scaled_dot_product_attention(q, k, v, attn_mask=mask)
  * run compiled torch.compile(same callable)(q, k, v)
  * print (#elements that differ, max abs diff, and where the mismatch is)

A correct backend gives mismatch=0 and maxdiff=0.0.
"""

import sys
import traceback

import torch
import torch.nn.functional as F

# torch_npu must be imported for the NPU device to be registered.
try:
    import torch_npu  # noqa: F401
except Exception:  # pragma: no cover
    traceback.print_exc()
    sys.exit("FATAL: `import torch_npu` failed (did you `source .../set_env.sh`?)")

# ----------------------------------------------------------------------------
# Problem configuration (same as reported in issue #2531)
# ----------------------------------------------------------------------------
SIZE = 96          # sequence length
NH = 4             # number of heads
HEAD_DIM = 32      # per-head feature dim
BATCH = 1
SEED = 0
DTYPES = (torch.float16, torch.bfloat16)


def build_inputs(dtype, device="npu"):
    """Return (q, k, v, additive_causal_mask) with a fixed seed.

    Generated on CPU then moved to `device`, so that a float32 CPU reference
    built with the same seed sees *exactly* the same underlying random values.
    """
    torch.manual_seed(SEED)
    q = torch.rand(BATCH, NH, SIZE, HEAD_DIM, dtype=torch.float32)
    k = torch.rand(BATCH, NH, SIZE, HEAD_DIM, dtype=torch.float32)
    v = torch.rand(BATCH, NH, SIZE, HEAD_DIM, dtype=torch.float32)
    idx = torch.arange(SIZE)
    causal = idx[:, None] >= idx[None, :]                      # (SIZE, SIZE) bool
    mask = torch.where(causal, 0.0, float("-inf"))             # float32 mask
    return (q.to(device=device, dtype=dtype),
            k.to(device=device, dtype=dtype),
            v.to(device=device, dtype=dtype),
            mask.to(device=device, dtype=dtype))


def reference_fp32():
    """Ground truth: float32 eager SDPA on CPU with the same values."""
    q, k, v, mask = build_inputs(torch.float32, device="cpu")
    with torch.no_grad():
        return F.scaled_dot_product_attention(q, k, v, attn_mask=mask)


def make_fn(mask):
    """The exact callable from the issue report."""
    return lambda a, b, c: F.scaled_dot_product_attention(a, b, c, attn_mask=mask)


def compare(name, dtype, q, k, v, mask):
    print("=" * 78)
    print(f"[{name}] dtype={dtype}  size={SIZE} nh={NH} head_dim={HEAD_DIM} seed={SEED}")
    print(f"[{name}] TORCHINDUCTOR_NPU_BACKEND={__import__('os').environ.get('TORCHINDUCTOR_NPU_BACKEND')}")
    print("=" * 78)

    fn = make_fn(mask)

    try:
        eager = fn(q, k, v)
    except Exception:
        print(f"[{name}] EAGER FAILED:")
        traceback.print_exc()
        return None

    try:
        compiled_fn = torch.compile(fn)
        comp = compiled_fn(q, k, v)
    except Exception:
        print(f"[{name}] TORCH.COMPILE FAILED:")
        traceback.print_exc()
        return None

    rtol = 1e-3
    atol = 1e-3
    total = eager.numel()
    close = torch.isclose(comp.float(), eager.float(), rtol=rtol, atol=atol)

    # Which side is wrong?  Compare both against a float32 CPU ground truth.
    try:
        ref = reference_fp32()
        e_cpu = eager.cpu().float()
        c_cpu = comp.cpu().float()
        r_ok = torch.isclose(e_cpu, ref, rtol=rtol, atol=atol)
        c_ok = torch.isclose(c_cpu, ref, rtol=rtol, atol=atol)
        print(f"[{name}] vs fp32 CPU reference:  eager bad = "
              f"{int((~r_ok).sum().item())}/{total},  compiled bad = {int((~c_ok).sum().item())}/{total}")
        print(f"[{name}] eager    vs fp32 maxdiff = {(e_cpu - ref).abs().max().item():.6f}")
        print(f"[{name}] compiled vs fp32 maxdiff = {(c_cpu - ref).abs().max().item():.6f}")
    except Exception:
        print(f"[{name}] (fp32 CPU reference unavailable)")
        traceback.print_exc()

    neq = int((eager != comp).sum().item())          # bitwise-inexact count
    ncl = int((~close).sum().item())                 # tolerance-exceed count
    maxdiff = (eager.float() - comp.float()).abs().max().item()

    print(f"[{name}] eager     absmax = {eager.abs().max().item():.6f}")
    print(f"[{name}] compiled  absmax = {comp.abs().max().item():.6f}")
    print(f"[{name}] mismatch (a != b)          = {neq}/{total}")
    print(f"[{name}] mismatch (rtol={rtol}, atol={atol} exceeded) = {ncl}/{total}")
    print(f"[{name}] maxdiff = {maxdiff:.6f}")

    # Where does it go wrong?  A causal-SDPA bug typically shows up on the
    # upper (masked) triangle, i.e. column index > row index.
    if ncl > 0:
        bad = (~close)[0, 0]                          # head 0, batch 0
        idx = bad.nonzero()
        if idx.numel():
            rows = idx[:, 0]
            cols = idx[:, 1]
            upper = int((cols > rows).sum().item())
            lower = int((cols <= rows).sum().item())
            visible_total = (SIZE * (SIZE + 1)) // 2   # lower+diag count per map
            print(f"[{name}] first bad (row,col) = ({rows[0].item()},{cols[0].item()})")
            print(f"[{name}] bad in MASKED upper triangle = {upper}, "
                  f"in VISIBLE lower triangle = {lower}  (head 0 / batch 0)")
            print(f"[{name}]   visible elements in that (96x96) map = {visible_total}")
        # show a few concrete numbers
        r0 = int(idx[0, 0]); c0 = int(idx[0, 1])
        print(f"[{name}]   eager[0,0,{r0},{c0}]    = {eager[0,0,r0,c0].item():.6f}")
        print(f"[{name}]   compiled[0,0,{r0},{c0}] = {comp[0,0,r0,c0].item():.6f}")

    verdict = "REPRODUCED (compiled != eager beyond fp16/bf16 exactness)" if neq else "NOT REPRODUCED (bitwise equal)"
    print(f"[{name}] VERDICT: {verdict}")
    print()
    return verdict


def main():
    device = "npu"
    if not torch_npu.npu.is_available():
        sys.exit("FATAL: torch_npu.npu.is_available() == False")
    print(f"device_name = {torch_npu.npu.get_device_name(0)}")
    print(f"torch       = {torch.__version__}")
    print(f"torch_npu   = {torch_npu.__version__}")
    import triton
    print(f"triton      = {triton.__version__}")
    import os
    print(f"ASCEND_HOME_PATH = {os.environ.get('ASCEND_HOME_PATH')}")
    print()

    for dt in DTYPES:
        q, k, v, mask = build_inputs(dt, device)
        compare("issue#2531", dt, q, k, v, mask)


if __name__ == "__main__":
    main()
```
