我们环境的 pip 包是 `triton-ascend 3.6.0+git0cfb1708`（`version.txt` 为 3.6.0，
而 `python/triton/__init__.py` 里是 `__version__ = '3.5.0'`），即我们跑的就是 TA 3.6.0，
与「TA 3.6.0 只兼容 CANN 9.1.0」的约束一致。后续我们一律写 pip 包版本。

### 按你们的要求在 CANN 9.1.0 上复跑：复现

自包含脚本（只依赖 torch + torch_npu + 标准库，不需要 pytest、不需要改安装树）。
`R0_BLOCK` 用后端自带的诊断旋钮 `torch_npu._inductor.triton_experimental.config.pin_xr` 固定，
每个配置独立进程（否则 triton 编译缓存会复用上一条）。

用例：`x = torch.rand(128, 256)` on npu，`torch.compile(lambda t: t.max(dim=1))`，
比较 compiled `.indices` 与 eager `.indices`（== `x.argmax(1)`）。

| R0_BLOCK | r-loop 是否切分 | CANN 9.1.0 index 错 | CANN 9.2.0-beta.2 index 错 | value 错 | (compiled − eager) 偏差集合 |
|---|---|---|---|---|---|
| 256 (= rnumel) | 否（1 trip） | 0/128 | 0/128 | 0/128 | {0} |
| 128 | 是（2 trips） | **55/128** | **55/128** | 0/128 | {−128, 0} |
| 64 | 是（4 trips） | **89/128** | **89/128** | 0/128 | {−192, −128, −64, 0} |

环境与 #2531 同一套（Ascend910B4 / torch 2.15.0.dev20260917+cpu /
torch_npu 2.15.0.dev20260917+gitec69335 / `TORCHINDUCTOR_NPU_BACKEND=triton_experimental`），
两臂**只换 `source /opt/ascend/cann-*/set_env.sh` 那一行**。

不 pin、走默认路径的 rnumel 扫描（CANN 9.1.0）：

| rnumel | 32 | 64 | 128 | 256 | 512 |
|---|---|---|---|---|---|
| index 错 | 0/128 | 0/128 | 64/128 | 89/128 | 0/128 |
| 偏差集合 | {0} | {0} | {−64, 0} | {−192,−128,−64,0} | {0} |

> 说明：issue 正文里的 `R0_BLOCK=128 → 16/128` 取自用例
> `test_dynamic_shapes_persistent_reduction_mixed_x_dim` 的实测；
> 上面 55/128、89/128 是我们这个最小用例 `rand(128,256)` 的读数，错因相同。

### 结论

1. 在 **CANN 9.1.0 上复现**，且与 9.2.0-beta.2 **逐字一致**（两臂数值完全相同）。
2. 变量是「r-loop 是否被切分」，与 CANN 版本无关：只要 `R0_BLOCK < rnumel` 就错，
   `R0_BLOCK == rnumel`（单 chunk）时正确。
3. 表现：**value 全对、只有 index 错**，且偏差恒为 chunk 大小的整数倍
   （`{−192,−128,−64,0}`）⇒ compiled 侧存的是 r-chunk **内部**的局部下标，丢了 chunk 偏移。
   首个错行：`true_argmax=129, eager=129, compiled=1, diff=−128`。
4. 这是**静默数值错**（不报错、不崩溃），只在 argmax/argmin 类用法上暴露，建议优先。

如果你们希望用更「真实」的触发方式（不 pin、靠尺寸自然切分），上表的 `rnumel=128 → 64/128`、
`rnumel=256 → 89/128` 是可直接复现的尺寸。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Self-contained reproduction for triton-ascend issue #2530
=========================================================
"Under the NPU triton_experimental backend, an argmax carried through a SPLIT
 r-loop loses the chunk offset: torch.max(x, dim=1).indices returns the local
 argmax within the last-processed r-chunk instead of the global one."
(Values are correct; only the indices are wrong.)

Dependencies: torch + torch_npu + Python stdlib ONLY.  No pytest, no test tree.

Usage (inside the NPU container, after sourcing the desired CANN env):
    source /opt/ascend/cann-9.1.0/set_env.sh          # or .../cann-9.2.0-beta.2/set_env.sh
    export TORCHINDUCTOR_NPU_BACKEND=triton_experimental
    /opt/miniconda/envs/npu/bin/python repro_2530.py

IMPORTANT: each configuration must run in a FRESH process (the triton
autotune/compile cache would otherwise serve a previously compiled kernel).
This script re-execs itself once per config, so just run it as shown.

What it does
------------
torch.max(x, dim=1) on x = rand(128, 256) on the NPU, under torch.compile.
The reduction is split into rnumel/R0_BLOCK trips. We compare the compiled
`indices` against the eager `indices` (== x.argmax(1)) for:
    R0_BLOCK = 256  -> r-loop NOT split (1 trip)      : expected correct
    R0_BLOCK = 128  -> r-loop split into 2 trips       : expected WRONG
    R0_BLOCK =  64  -> r-loop split into 4 trips       : expected WRONG
R0_BLOCK is forced through the backend's own diagnostic knob
`torch_npu._inductor.triton_experimental.config.pin_xr` (documented in-tree as
"TEMP diagnostic: pin a single (XBLOCK, R0_BLOCK)").  We deliberately do NOT
touch any installed file.
"""

import os
import re
import subprocess
import sys

ROWS = 128
RNUMEL = 256
PINS = ["1,256", "1,128", "1,64"]


def child(pin):
    """Run one configuration in this (fresh) process and print the result."""
    import torch
    import torch_npu  # noqa: F401
    import torch._dynamo as dyn
    from torch._inductor.utils import run_and_get_code, fresh_cache
    from torch_npu._inductor.triton_experimental import config as ncfg

    ncfg.pin_xr = pin
    x, r0, r1 = None, None, None
    torch.manual_seed(0)
    x = torch.rand(ROWS, RNUMEL, device="npu")
    ev, ei = x.max(dim=1)                       # eager reference
    true_idx = x.argmax(dim=1)                  # ground truth

    with fresh_cache():
        dyn.reset()
        with torch._inductor.config.patch({"combo_kernels": False}):
            (gv, gi), code = run_and_get_code(torch.compile(lambda t: t.max(dim=1)), x)

    vb = int((gv != ev).sum().item())
    ib = int((gi != ei).sum().item())
    tb = int((gi != true_idx).sum().item())
    diffs = sorted(set((gi - ei).flatten().tolist()))
    print(f"[pin={pin}] rnumel={RNUMEL} rows={ROWS}")
    print(f"[pin={pin}]   value-mismatch-rows = {vb}/{ROWS}")
    print(f"[pin={pin}]   index-mismatch vs eager   = {ib}/{ROWS}  (vs x.argmax = {tb}/{ROWS})")
    print(f"[pin={pin}]   (compiled - eager) index diffs = {diffs}")
    if ib:
        bad = (gi != ei).nonzero().flatten()
        r0 = int(bad[0])
        print(f"[pin={pin}]   first bad row {r0}: true_argmax={int(true_idx[r0])} "
              f"eager={int(ei[r0])} compiled={int(gi[r0])} "
              f"diff={int(gi[r0]) - int(ei[r0])}")
    print(f"[pin={pin}]   VERDICT: "
          f"{'REPRODUCED (indices wrong while values are right)' if ib else 'not reproduced (indices correct)'}")
    return ib


def main():
    if len(sys.argv) == 2 and sys.argv[1].startswith("--child="):
        child(sys.argv[1].split("=", 1)[1])
        return

    import torch, torch_npu
    import triton
    print("=" * 78)
    print(f"torch     = {torch.__version__}")
    print(f"torch_npu = {torch_npu.__version__}")
    print(f"triton    = {triton.__version__}")
    print(f"ASCEND_HOME_PATH = {os.environ.get('ASCEND_HOME_PATH')}")
    print(f"TORCHINDUCTOR_NPU_BACKEND = {os.environ.get('TORCHINDUCTOR_NPU_BACKEND')}")
    print(f"device    = {torch_npu.npu.get_device_name(0)}")
    print("=" * 78)

    for pin in PINS:
        # fresh process per pin: the triton cache would otherwise be reused
        subprocess.run([sys.executable, __file__, f"--child={pin}"], check=True)


if __name__ == "__main__":
    main()
```
