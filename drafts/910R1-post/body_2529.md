这条我们**无法在 CANN 9.1.0 上复现 segfault**，如实说明排查过程和目前的观察。

### 1. 按 issue 里的路径在 CANN 9.1.0 上复跑：用例被 SKIP，未能验证

字面命令（`pytest -q test/inductor/test_combo_kernels.py -k "test_reduce_functions"`）在
CANN 9.1.0 与 9.2.0-beta.2 上**两臂均 `2 skipped, exit=0`**：

```text
SKIPPED [0.0012s] [2] test_combo_kernels.py:425: requires gpu and triton
```

原因是该用例带 `@requires_gpu_and_triton`，而 NPU 不满足它的 GPU 判定（NPU 不算 GPU 的历史坑）。
⇒ **本用例在 NPU 上被整体跳过，未能验证**（这**不等于**「不复现」）。

（另外一个与本 issue 无关的小坑：该字面命令若在 cwd 下存在未编译的 `torch/` 源码树，
会 ImportError；把 cwd 换到 `/tmp`、用绝对路径即可正常收集。）

### 2. 为真正触达该用例，用运行期 shim 打开了这个门（不改安装树）

用只 setattr 已导入模块的方式绕过 `requires_gpu_and_triton`（不动任何安装文件）后：

| 臂 | 结果 |
|---|---|
| CANN 9.1.0 | `rc=1` FAIL — `NoTritonConfigsError` / `CompilationError` / `NameError('x0_blocks is not defined')` |
| CANN 9.2.0-beta.2 | `rc=1` FAIL — 同一错误 |

**两臂都没有 segfault（无 139 / SIGSEGV）。** 失败发生在**编译期**，
生成的 `triton_unk_fused_0` 里这一行引用了未定义的 `x0_blocks`：

### 3. 直接探针（显式开组合核 + 同进程连续编译）

另一条路径：显式打开组合核、同进程连续编译 4 个图 + 3 次重复编译

失败者同样是**编译期** `NameError`（`x0_blocks` / `x0` 未定义），不是崩溃。

### 4. 结论与请求

- 在 **CANN 9.1.0 上未观察到 segfault**：字面用例被 skip（未能验证）；
  强开门与直接探针两条路径都是**编译期 NameError**，不是 139。
- 我们原始报告里的 segfault 可能来自**另一条触发路径**（或与当时的组合核开关 /
  `combo_kernel_per_subkernel_blocks` 组合、以及原报告的 910B2 环境有关），
  目前我们**无法稳定复现**，因此不敢断言它在 9.1.0 上的状态。我们也在继续核对当初那条路径。
- 🙋 **请指教**：这条 segfault 在你们那边应如何触发（例如具体 test id / 开关组合 / 连续编译次数）？
  按你们给的路径我们再跑 9.1.0，比我们盲猜更有效率。
- 另：上面那个 `NameError('x0_blocks is not defined')`（组合核未发射 `x0_blocks` 定义）看起来是
  **另一个**真实缺陷，CANN 9.1.0 与 9.2.0-beta.2 两臂都中。如果它其实与本 issue 同源，请告知，

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Direct probe for issue #2529 ("launcher segfaults when combo kernels are
compiled consecutively"): compile several combo-kernel graphs back to back in
ONE process and see whether the process dies with SIGSEGV (exit 139).

Deps: torch + torch_npu only.

Run under the NPU backend:
    source /opt/ascend/cann-9.1.0/set_env.sh
    export TORCHINDUCTOR_NPU_BACKEND=triton_experimental
    /opt/miniconda/envs/npu/bin/python probe_2529.py ; echo EXIT=$?
"""
import os
import sys
import traceback

import torch
import torch_npu  # noqa: F401
import torch._dynamo as dyn


def fn_reduce(a, b, c, d):
    # same shape family as upstream test_reduce_functions
    return a.sum(0), b.max(0).values, c.min(0).values, torch.nn.functional.tanh(d)


def fn_mixed(a, b, c):
    return a.sum(1), b.mean(1), c.cumsum(1)


CASES = [
    ("reduce_functions", fn_reduce,
     [torch.rand(10, 10, device="npu"), torch.rand(20, 20, device="npu"),
      torch.rand(10, 10, device="npu"), torch.rand(30, 8, device="npu")]),
    ("mixed_1", fn_mixed,
     [torch.rand(16, 128, device="npu"), torch.rand(32, 128, device="npu"),
      torch.rand(32, 256, device="npu")]),
    ("mixed_2", fn_mixed,
     [torch.rand(24, 96, device="npu"), torch.rand(48, 96, device="npu"),
      torch.rand(48, 192, device="npu")]),
    ("mixed_3", fn_mixed,
     [torch.rand(8, 64, device="npu"), torch.rand(16, 64, device="npu"),
      torch.rand(16, 128, device="npu")]),
]


def main():
    print(f"torch={torch.__version__} ASCEND_HOME_PATH={os.environ.get('ASCEND_HOME_PATH')}",
          flush=True)
    per_sub = os.environ.get("PER_SUB", "0") == "1"
    print(f"combo_kernels=True combo_kernel_per_subkernel_blocks={per_sub}", flush=True)
    # issue #2529 is about COMBO kernels; force them on for every compile
    cfg = {"combo_kernels": True, "benchmark_combo_kernel": False,
           "combo_kernel_per_subkernel_blocks": per_sub}
    for i, (name, fn, inps) in enumerate(CASES):
        print(f"[{i}] compiling {name} ...", flush=True)
        try:
            with torch._inductor.config.patch(cfg):
                out = torch.compile(fn)(*inps)
            print(f"[{i}]   OK; n_out={len(out) if isinstance(out, tuple) else 1}", flush=True)
        except Exception as e:
            print(f"[{i}]   FAILED: {type(e).__name__}: {str(e)[:400]}", flush=True)
    # consecutive recompiles of the same fn (fresh dynamo each time) -- the
    # "consecutive compile" pattern the issue blames for the launcher segfault.
    for r in range(3):
        print(f"[r{r}] recompiling mixed_2 ...", flush=True)
        try:
            dyn.reset()
            fn = CASES[2][1]
            with torch._inductor.config.patch(cfg):
                torch.compile(fn)(*CASES[2][2])
            print(f"[r{r}]   OK", flush=True)
        except Exception as e:
            print(f"[r{r}]   FAILED: {type(e).__name__}: {str(e)[:300]}", flush=True)
    print("ALL_DONE_NO_SEGFAULT", flush=True)


if __name__ == "__main__":
    main()
