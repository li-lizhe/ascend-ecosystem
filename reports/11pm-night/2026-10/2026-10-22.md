## 三、缺陷与修法

### 3.1 靶点

issue **#14**（`开源报告生成失败时 runner 仍返回成功`，2026-10-04 报，0 评论、0 assignee）。
基线：`master` @ `8ebf3ccccd812e8a96338c9beed08654d708d27a`（2026-10-21）。

### 3.2 根因（读 master 源码确认，非照抄 issue）

`scripts/run_tests.py`：

```python
def finalize_reports(paths, results, args, has_npu) -> None:   # ← 返回 None
    ...
    gen_rc = generate_opensource_report(paths.results_json, paths.opensource)
    if gen_rc != 0:
        print(f"[test] opensource report failed rc={gen_rc}", file=sys.stderr)
    # ← gen_rc 到这里就丢了

def main(argv=None) -> int:
    ...
    finally:
        finalize_reports(paths, results, args, ctx.has_npu)   # ← 不接收返回值
    if paths.opensource is not None and not paths.opensource.is_file():
        return 1
    return 1 if failed else 0        # ← 只看用例失败数
```

`main()` 既拿不到生成器退出码，判据又只是「目标文件**是否存在**」。
当目标路径上还留着上一次的报告文件时，「本次生成失败」与「本次生成成功」在退出码上完全一致 ⇒
CI / 自动化会把**陈旧报告当成本次结果**。

### 3.3 修法（+12/−3，1 个源文件 + 1 个新测试文件）

- `finalize_reports()` 改为 `-> int`，未请求该报告时返回 `0`，否则返回 `gen_rc`；
- `main()` 用 `report_rc` 接收（先初始化为 `0`，因在 `finally` 里赋值），非零即 `return 1`；
- 报告写出顺序、报告内容、套件编排、`--report` / `--results-json` 行为均不变。

分支 `fix/report-generation-exit-status`，head `6c43336255c285bb1f06bee8976b3de431dc03ad`，
author = committer = `lizhe <147392333@qq.com>`（CANN 仓口径）。
