## 三、缺陷与修法

### 3.1 靶点

issue **#369**（`内存泄漏 - 文件 expert_token_dispatcher_op.cpp - 函数 ExpertTokenDispatcher - 行号 66`，
2026-09-22 报，1 评论、0 assignee，评论明确欢迎社区提 PR）。

文件：`integration/custom/deepseek-v3-ascend310p/src/cpp/mlguider_llm_ascend/core/layers/expert_token_dispatcher_op.cpp`
基线：`master` @ `a06336361c2614c7bcaebcb9046181a9e23008f7`（2026-10-23 同步，含 DSpark 宽度逻辑调整）。

### 3.2 根因（读 master 源码确认，非照抄 issue）

```cpp
int64_t syncLength = DEFAULT_SYNCALL_NEED_SIZE * CORE_NUM_310P3;   // 20 * 8 = 160
void* g = nullptr;
auto ret = aclrtMalloc(&g, syncLength * 4, ACL_MEM_MALLOC_HUGE_FIRST);  // 640 B
aclgten = aclCreateTensor(..., g);        // 只把地址交给描述符
```

`aclDestroyTensor(aclgten)` 释放描述符、**不释放**底层设备内存；函数里三条路径全无 `aclrtFree(g)`。
另外第二条失败路径还多漏一块：`workspaceAddr` 在 `aclnnMiExpertTokenDispatcher` 之前已 `aclrtMalloc`，
该 `throw` 之前没有释放（上游 22 个 layer 文件里只有 `expert_token_dispatcher_op.cpp` 与
`linear_op.cpp` 的 `LinearI8(void**, ...)` 重载出现 malloc/free 不配对，本轮只修前者，后者是**输出参数**不是泄漏）。

该函数经 `deepseek_v3_w8a8_model.cpp:908` 的 `DeepSeekV3MoEInfer` 在 MoE 前向中逐层调用
⇒ 每次前向、每层泄漏 640 B，多层多步持续累积。

### 3.3 修法（+7 行，1 个源文件）

- 成功路径补 `aclrtFree(g)`；
- `GetWorkspaceSize` 失败路径补 `aclrtFree(g)`；
- 执行失败路径补 `aclrtFree(workspaceAddr)`（`workspaceSize > 0` 时）与 `aclrtFree(g)`。

分支 `fix/expert-token-dispatcher-sync-buffer-leak`，head `72df2dd`，tree `aa7575c3140c02b8c7b083ad4f4b7e331fbc2c38`，
author = committer = `li-lizhe <147392333@qq.com>`（CANN 仓口径）。blob 行尾 **CR=0 / LF=130**（LF 合规）。

## 六、对外留痕

### 6.1 commit message（已推送，head `72df2dd`）

```
fix(deepseek-v3-ascend310p): release the sync buffer on the failure paths

ExpertTokenDispatcher allocates a 640-byte device buffer for the output
sync tensor (syncLength = DEFAULT_SYNCALL_NEED_SIZE * CORE_NUM_310P3 =
160 int32) and gives it to aclCreateTensor as the tensor address.
Destroying that descriptor does not free the memory, and the function has
no aclrtFree for it on any path:

- on success only aclDestroyTensor x7 and aclrtFree(workspaceAddr) run;
- both error paths throw directly.

The function is called from DeepSeekV3MoEInfer once per MoE layer, so
every forward pass accumulates 640 bytes of unreleased device memory.

Release g on the success path and on both failure paths, and release the
workspace buffer on the second failure path as well (it is allocated
before the execute call and, like g, is not owned by any descriptor).

No behaviour change on the successful path other than the added free.

Signed-off-by: li-lizhe <147392333@qq.com>
```

### 问题（对应 #369）

`ExpertTokenDispatcher` 为输出 sync tensor 分配一块设备内存，用完后没有释放：

`aclDestroyTensor(aclgten)` 释放的是描述符，不是底层设备内存；而函数里**三条路径都没有 `aclrtFree(g)`**：

- 成功路径补 `aclrtFree(g)`；
- 第一条失败路径补 `aclrtFree(g)`；
