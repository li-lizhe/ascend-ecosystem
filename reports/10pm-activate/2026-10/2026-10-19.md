- 改动：**2 文件** — `fastvideo/distributed/communication_op.py` **+10/−3**、
  新增 `fastvideo/tests/distributed/test_sp_warmup_device.py` **+97/−0**
- 问题：`warmup_sequence_parallel_communication()`（`ComposedPipelineBase` 在 SP>1 时必调）默认设备写死
  `torch.device("cuda")`、结尾 `torch.cuda.synchronize(device)` ⇒ 非 CUDA 构建（Ascend NPU / MPS）上
  warmup 张量分配即崩 `AssertionError: Torch not compiled with CUDA enabled`，**SP 多卡一跑就挂**。
- 改法：默认设备改成仓库自己的平台抽象 `current_platform.device_type`、同步改成
  `current_platform.get_torch_device().synchronize(device)`；显式传 `device=` 的调用方不受影响。
  `from fastvideo.platforms import current_platform` 按仓库惯例放在**函数内**（`distributed/parallel_state.py`
  六处同样写法）。CUDA/CPU 行为不变。

## 验证（原文）

环境：ssh 177 → 容器 npu-lizhe，**4×Ascend 910B2**，`torch 2.15.0.dev20260917+cpu` /
`torch_npu 2.15.0.dev20260917+gitec69335`，backend=HCCL，2 rank
`python3 -m torch.distributed.run --nproc_per_node=2`，用**真 process group** 驱动真正被改的函数
（FastVideo 本体在该容器装不上依赖，故只 import 目标文件 + 替身依赖）。

```
=== UPSTREAM (main @ 0033a9b) ===
[rank 0] RESULT: AssertionError: Torch not compiled with CUDA enabled
[rank 1] RESULT: AssertionError: Torch not compiled with CUDA enabled
=== PATCHED ===
[rank 1] RESULT: OK    warmup tensors on: ['npu:1']   synchronize calls: ['npu(npu)']   real collectives: 3
[rank 0] RESULT: OK    warmup tensors on: ['npu:0']   synchronize calls: ['npu(npu)']   real collectives: 3
```

每个 rank 的 warmup 张量落在自己的卡上（npu:0 / npu:1），all-to-all / all-gather warmup 真的在 HCCL 上跑通。
本机另用 torch 2.8.0+cpu 单进程跑同一 harness，同样是「上游崩 / 修后 OK」。

**未测（诚实标注）**：CUDA/NCCL 机器（手头没有）、端到端 FastVideo pipeline（NPU 容器缺其依赖）。
