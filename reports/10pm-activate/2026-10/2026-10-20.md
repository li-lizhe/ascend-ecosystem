The diarization (Nemotron streaming diarization) and speech-to-viseme stages each carry their own
supported-device list, and both omit `npu`:

* `src/speech_to_speech/diarization/streaming.py`: `DIARIZATION_DEVICES = ("cuda", "mps", "cpu")`

* update the two `--help` strings and the CPU-fallback warning to mention NPU;
* add a regression test covering the `auto` resolution order for both device lists.

## Summary

`ModelManager.__init__` resolves the device the server runs on with two fallbacks that fire
unconditionally:

```python
elif torch.backends.mps.is_available():
    self.device = "mps"
elif not torch.cuda.is_available():
    self.device = "cpu"
```

Both overwrite whatever `--device` asked for, so on any machine without a working CUDA device an
explicit `--device npu` (or any other explicitly named accelerator) is silently replaced by `cpu`,

difference for the other spellings is that an explicit request is no longer overwritten - e.g.
`--device cpu` on a Mac with MPS now stays CPU, and `--device npu` stays `npu`.
