## 3. 问题与改法

**文件**：`lmdeploy/pytorch/backends/dlinfer/moe.py`

```python
if self.ep_size > 1:
    self.expert_ids_per_ep_rank = torch.tensor(
        [i % (self.num_experts // self.ep_size) for i in range(num_experts)],
        dtype=torch.int32,
        device=torch.cuda.current_device(),   # ← dlinfer 后端服务 Ascend/MACA/CAMBRICON，全非 CUDA
    )
```

`dlinfer` 这个后端存在的意义就是跑非 CUDA 设备，`torch.cuda.current_device()` 在这些机器上直接
`AssertionError: Torch not compiled with CUDA enabled` ⇒ **任何 `ep_size > 1` 的 MoE 层在建层阶段就崩**。
git 历史（GitHub API 逐版本取文件）显示这行自 2026-02 的 #3696（`[ascend]suppot ep`）就在，长期潜伏。

**改法**（延续本仓 #4986 被接受的写法：构造期不留设备假设、用的时候按输入 tensor 的 device 处理）：

- `__init__` 不再建映射；
- 新增 `_get_expert_ids_per_ep_rank(device)`，按传入 device 建、带缓存（device 变了才重建）；
- `DlinferFusedMoEImpl.forward` 与 `DlinferFusedMoEW8A8Impl.forward` 都用 `hidden_states.device` 取映射。

CUDA 上行为等价：同一张 tensor、同一个 device，只是晚一步建。

排查中主动排除的「伪靶点」（都读过了，别重复踩）：
`lmdeploy/pytorch/engine/cache_engine/{engine,state}.py` 里的 `device='cuda'` 有注释说明是**故意**的
（非 CUDA 集成会在更上层 patch 这条规范路径）；`backends/cuda/token_dispatcher.py` 的同款只在 CUDA 后端被实例化。
