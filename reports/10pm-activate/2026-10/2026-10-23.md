### 对外正文留痕（建 PR 前落盘，发出后不改写）

- 标题：`fix(lora): resolve prefixed PEFT keys in the native loader`
- head：`li-lizhe:fix/lora-native-peft-prefixed-keys` → base：`dev`
- body：

```
## Description

Fixes #5174.

`load_safetensors` folds the trailing `alpha` / `weight` / `lora_up` / `lora_down` markers of a prefixed key into the network part, but a diffusers PEFT adapter names the pair `lora_A` / `lora_B`, which the loop did not recognise. For a key such as

    transformer.transformer_blocks.0.attn.to_q.lora_A.weight

only `weight` was consumed, so `lora_A` stayed on the module key (`lora_transformer_transformer_blocks_0_attn_to_q_lora_A`), no module matched, and the adapter was dropped while the API still returned HTTP 200 with base-model output.

This folds `lora_A` / `lora_B` into the network part and normalizes them to `lora_down` / `lora_up`, which is what the unprefixed PEFT branch already produces, so both paths now agree.

## Notes

- Only the accepted marker list and the normalization of the network part change; the module key is built exactly as before, so keys that already resolved keep resolving to the same module.
- Keys that match nothing are still collected in `keys_failed_to_match`, so an unknown module still warns instead of landing on a near neighbour.

## Environment and Testing

Added `test/test-lora-native-peft-keys.py`, an offline test in the style of the other `test/test-*.py` files: it stubs the loader's sibling modules and exercises the real `modules/lora/lora_load.py` plus `modules/lora/lora_convert.py`.

    python test/test-lora-native-peft-keys.py

- before the change: 4 passed, 3 failed - the prefixed PEFT case builds no network and matches nothing
- after the change: 7 passed, 0 failed

Run on a torch-only CPU environment (torch 2.10.0+cpu, Python 3.12) with no GPU, no running server and no model file: the change is key-name handling only, with no device or dtype behaviour in the path.
```

## 2. axolotl-ai-cloud/axolotl — strided EBFT 特征网络被硬编码到 cuda 设备

- **仓**：axolotl-ai-cloud/axolotl（促活池，空窗 23 天；上一 PR #3995 已于 2026-09-30 合入）
- **上游基准**：`git reset --hard origin/main` = `ce568e3791dde3f41aca481dd2966fefbbc5f21d`（2026-10-23）
- **问题文件**：`src/axolotl/core/trainers/ebft/strided.py`（EBFT strided 训练器，2026-03 随 #3527 引入、2026-10-21 仍在维护）
- **根因（实测坐实）**：特征网络的设备选择整段写死 cuda：
  - `visible_gpus = torch.cuda.device_count()` ⇒ 非 CUDA 加速器上恒为 0，**静默**改变分支（丢掉 PEFT 共享权重优化 / 多卡深拷贝分支）；
  - 三处 `torch.device(f"cuda:{actor_gpu}")` + 一处 `f"cuda:{(actor_gpu + 1) % visible_gpus}"` ⇒ actor 在 `npu:0` 时特征网络被放到 `cuda:0`（多卡分支为 `cuda:1`）；
  - `actor_gpu` 只承认 `original_device.type == "cuda"`；
  - 单卡深拷贝分支的 `_FLEX_ATTENTION_AVAILABLE` 未判设备类型（多卡分支判了），非 CUDA 上会去开 flex_attention。
- **改法**：走仓库自己的 `axolotl.utils.distributed.get_device_type()` / `get_device_count()`（model loaders / bench.py 已在用），新增 8 行 `_feature_device_type()`（cpu/meta 占位回退到本次运行的设备类型，其余保留 actor 的加速器类型），并把单卡分支的 flex 判定对齐多卡分支。2 文件 +61/−11。
- **撞车审计**：该仓 open PR 中唯一同向的是 **#4133「Feat/tpu support」**（s6r6k）——它改 `utils/distributed.py`（新增 `is_xla`/`get_device_str`/`empty_device_cache`）与 `loaders/model.py`，**未触及 strided.py**；本改动只用 main 上已有的 `get_device_type/get_device_count`，不依赖该 PR。搜索 `type:pr is:open ebft` / `strided` 无其它占用该文件的 PR。

### 对外正文留痕（建 PR 前落盘，发出后不改写）

- 标题：`fix(ebft): place the strided feature network on the actor's accelerator`
- head：`li-lizhe:fix/ebft-strided-feature-device` → base：`main`
- body：

```
## Description

The strided EBFT trainer creates a frozen feature network next to the actor. It built that network on a hardcoded `cuda` device and read the device count from `torch.cuda`:

```python
actor_gpu = (
    original_device.index
    if (original_device.type == "cuda" and original_device.index is not None)
    else 0
)
visible_gpus = torch.cuda.device_count()
...
self._feature_device = torch.device(f"cuda:{actor_gpu}")
```

On a run whose accelerator is not CUDA (NPU, XPU, ...) this places the feature network on `cuda:0` - or `cuda:1` in the multi-device branch - while the actor lives on another device, and `torch.cuda.device_count()` returning 0 silently changes which branch builds the network.

This resolves the device type and the device count through `axolotl.utils.distributed.get_device_type()` / `get_device_count()` - what the model loaders and `bench.py` already use - so the feature network follows the actor onto its accelerator. A `cpu` or `meta` placeholder still falls back to this run's device type. The single-device deepcopy branch also guards `flex_attention` on the device type, the way the multi-device branch above it already does.

## Notes

- Behaviour on CUDA is unchanged: `get_device_type()` is `cuda` there and the resolved `torch.device` is the one the old device string built.
- `_feature_device_type()` is the only new function and the trainer's `__init__` calls it in a single place.

## Environment and Testing

`tests/test_ebft_strided_feature_device.py` covers the mapping: cuda/xpu/npu keep the actor's accelerator type, cpu/meta fall back to the run's device type.

Offline A/B of the real "Feature network setup" block - both revisions of `strided.py`, extracted and executed unchanged with the model, peft and pybind objects stubbed, and the same device count fed to both revisions (torch 2.10.0+cpu, no accelerator attached):

| case | before | after |
|---|---|---|
| actor on `npu:0`, peft, 1 device | `cuda:0` | `npu:0` |
| actor on `npu:0`, peft, 8 devices | `cuda:1`, flex on | `npu:1`, flex off |
| actor on `cuda:0`, peft, 1 device | `cuda:0` | `cuda:0` |
| actor on `cuda:1`, non-peft, 2 devices | `cuda:0` | `cuda:0` |
| actor on `meta`, 1 device | `cuda:0` | `cuda:0` |
| actor on `cpu`, 1 device | `cuda:0` | `cpu:0` |

Not tested: a real NPU/XPU run of this trainer (no such device on the box used), and the rest of this trainer's device handling, which is untouched here.

`ruff check` and `ruff format --check` are clean on both files.
