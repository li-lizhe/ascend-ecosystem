## 3. 问题与改动

**问题**：六个入口各自手写一份默认设备链，只认 CUDA / XPU / MPS：

```python
"cuda" if torch.cuda.is_available() else "xpu" if torch.xpu.is_available() else "mps" if ... else "cpu"
```

在装有 `torch_npu` 的昇腾机器上 `torch.cuda.is_available()` 恒为 `False` ⇒ **推理 / socket 服务 / finetune_gradio / UTMOS 评估全部静默落回 CPU**（不是报错，是白跑）。

**改动**（fork 分支 `fix/default-device-accelerator-resolution`，base=main `d852486451313ab31924303f6120e1aa19a208ce`，即上游 main 当前 HEAD；**7 文件 +57/−48**）：

- 新增 `src/f5_tts/device_utils.py`（44 行）：
  - `get_default_device()` 先问 `torch.accelerator.current_accelerator()`（PyTorch ≥ 2.6，报的是**真正注册且可用**的后端：cuda / npu / xpu / …），老版本回退到 `cuda → npu → xpu → mps → cpu` 显式探测；
  - `is_npu_available()` 里**惰性** `import torch_npu`（`try/except ImportError: return False`）⇒ CUDA/CPU/XPU 装机不引入任何新依赖、也不会因缺包报错。
- 六处调用点统一走它：`infer/utils_infer.py`、`infer/speech_edit.py`、`api.py`（顺带删掉那块 `import torch`，改后该文件已不再用 torch）、`socket_server.py`、`train/finetune_gradio.py`、`eval/eval_utmos.py`。
  - `eval/utils_eval.py` 的 ASR / run_sim 分支**故意不动**：那是 faster-whisper(CTranslate2) 与单卡 `cuda:{rank}` 路径，CTranslate2 无 NPU 后端，且改 rank→卡映射属「多进程真机验证」类改动，超出本轮范围。
