## 四、缺陷与修法（一句话）

`oumi torchrun` / `oumi accelerate` 在**没有集群调度器**（SkyPilot/Polaris/Slurm）时，
唯一的启动闸门 `_detect_local_machine_process_run_info()` 只看 `torch.cuda`：
本机若有别的加速器（昇腾 NPU 满足 `torch.cuda.is_available() == False`），
`oumi torchrun` 在拉起 `torchrun` 之前就直接
`RuntimeError: No supported distributed backends found and no GPUs on local machine!`；
Slurm 路径同样写死 `gpus_per_node = torch.cuda.device_count()`
（非 CUDA 节点会算出 `--nproc-per-node=0`）。

修法（2 处调用点 + 1 个 6 行 helper，CPU-only 行为不变）：
新增 `_get_accelerator_device_count()` —— `torch.accelerator.current_accelerator() is None` ⇒ 0，
否则 `torch.accelerator.device_count()`（torch.accelerator 报的是**当前活跃加速器**：
CUDA/NPU/XPU/MPS）；本机检测与 Slurm 检测都改用它。
`import torch` 仍保持函数内延迟导入；删掉了原来那条「CUDA 可用但 0 卡」的冗余分支
（两种情况都归并为 `device_count == 0`）。oumi 的 `pyproject.toml` 钉 `torch>=2.6`，
`torch.accelerator` 可用。

### 6.1 自建 issue 正文（English，实际发出的即下方全文）

```markdown
### What happens

`oumi torchrun` / `oumi accelerate` refuse to start on a local machine (no
SkyPilot / Polaris / Slurm detected) whenever `torch.cuda.is_available()` is
`False`, even when the machine does have another accelerator with usable devices:

    RuntimeError: No supported distributed backends found and no GPUs on local machine!

`_detect_local_machine_process_run_info()` in `src/oumi/cli/distributed_run.py` is
the last gate before the `torchrun` process is spawned, and it looks exclusively at
`torch.cuda`. `_detect_slurm_process_run_info()` makes the same assumption
(`gpus_per_node = torch.cuda.device_count()`), so a Slurm node whose devices are not
CUDA would ask for `--nproc-per-node=0`.

### Evidence on real hardware

Ascend 910B host (aarch64, 4 devices), `torch 2.15.0.dev` + `torch_npu`:

    torch.accelerator.current_accelerator() : npu
    torch.accelerator.device_count()        : 4
    torch.cuda.is_available()               : False
    torch.cuda.device_count()               : 0

    # calling the real _detect_local_machine_process_run_info({}) from main
    RAISED RuntimeError: No supported distributed backends found and no GPUs on local machine!

The same host runs a 4-process HCCL job fine, so those 4 devices are real and usable:

    $ torchrun --nproc_per_node=4 dist_check.py
    rank 0/4 local_rank=0 device=npu:0 all_reduce_sum=10.0
    rank 1/4 local_rank=1 device=npu:1 all_reduce_sum=10.0
    rank 2/4 local_rank=2 device=npu:2 all_reduce_sum=10.0
    rank 3/4 local_rank=3 device=npu:3 all_reduce_sum=10.0

### Expected behaviour

Device discovery should follow the active accelerator (`torch.accelerator`), so a
host with an NPU / XPU / other non-CUDA accelerator can launch, while a CPU-only
host keeps failing with the same error.

I have a patch for this (one file plus the matching unit tests) and will send a PR.
```

### 6.2 PR 正文（English，实际发出的即下方全文；`Fixes #2719`）

```markdown
## What

`oumi torchrun` / `oumi accelerate` refused to start on a local machine (no
SkyPilot / Polaris / Slurm detected) whenever `torch.cuda.is_available()` was
`False`, even when the machine had another accelerator with usable devices:

    RuntimeError: No supported distributed backends found and no GPUs on local machine!

`_detect_local_machine_process_run_info()` gated the launch on `torch.cuda` only, and
`_detect_slurm_process_run_info()` made the same assumption when computing
`--nproc-per-node`. Both now resolve devices through `torch.accelerator`, which reports
the active accelerator (CUDA / NPU / XPU / MPS) and its device count. CPU-only machines
still raise the same error, so behaviour there is unchanged.

Fixes #2719

## Verification

Real hardware: Ascend 910B host (aarch64, 4 devices, `torch 2.15.0.dev` + `torch_npu`,
`torch.cuda.is_available() == False`). The real `_detect_local_machine_process_run_info({})`
was loaded from `main` and from this branch and called on that host:

    # main
    RAISED RuntimeError: No supported distributed backends found and no GPUs on local machine!

    # this branch
    RESULT: {'node_rank': 0, 'num_nodes': 1, 'gpus_per_node': 4, 'total_gpus': 4,
             'master_address': '127.0.0.1', 'master_port': 8007, 'node_ips': ['127.0.0.1']}

The same host, running a real multi-process job on those devices, confirms that 4 is the
correct `--nproc-per-node` value:

    $ torchrun --nproc_per_node=4 dist_check.py
    rank 0/4 local_rank=0 device=npu:0 all_reduce_sum=10.0
    rank 1/4 local_rank=1 device=npu:1 all_reduce_sum=10.0
    rank 2/4 local_rank=2 device=npu:2 all_reduce_sum=10.0
    rank 3/4 local_rank=3 device=npu:3 all_reduce_sum=10.0

Unit tests, `pytest tests/unit/cli/test_cli_distributed_run.py`:

* `main`: 28 passed, 1 failed
* this branch: 30 passed, 1 failed
* the single failure is `test_torchrun_polaris_multi_gpu`, which fails identically
  without this change in the environment used here
* the new `test_torchrun_localmachine_non_cuda_accelerator` fails on `main` with
  `RuntimeError: ... no GPUs on local machine!` and passes with this change (RED → GREEN)
* the tests were run with `--noconftest` because the repository `tests/conftest.py`
  imports `datasets` and `aioresponses`, which could not be installed in the
  environment used here; both revisions were compared in the same environment

`ruff check` and `ruff format --check` (ruff 0.15.0, as pinned by pre-commit) are clean
for both files.

## Not tested

* End-to-end `oumi train` on an NPU host: the Ascend machine used for the evidence above
  has `torch` / `torch_npu` but not oumi installed, so only the launch detection was
  exercised there.
* Real CUDA and MPS hardware: those paths are not modified by this change, but they were
  not run on real devices here.

## AI assistance

This change was prepared with AI assistance. The contributor reviewed the diff and this
description and approved publishing it.
```
