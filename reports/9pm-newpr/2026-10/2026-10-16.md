## ⚠️ 本轮踩到的坑（可复用）

1. **`npu_channel.py` 的 ssh 通道会落在 169，而 169 上没有可用 torch_npu**：169 的 `npu-lizhe` 只有 `/usr/local/Ascend/driver`（无 CANN），`import torch_npu` 报 `libhccl.so: cannot open shared object file`；169 的 `/workspace/envs/env-pytorch-2.14` 反而因 triton 双重注册直接 `RuntimeError: Only a single TORCH_LIBRARY can be used to register the namespace triton`。
   **可用的真机在 177**：Windows 直连 `root@192.168.9.177`（通！）→ 容器 `npu-lizhe` → `/opt/miniconda/envs/npu/bin/python3`，CANN 在 **`/opt/ascend/ascend-toolkit/set_env.sh`**（不是 `/usr/local/Ascend/...`）。
2. **大文件别塞进 ssh 命令行**：base64 内联（18KB→1.8 万字符）会被 MSYS 的引号规则吞掉，表现为远端 `unmatched "` / `docker: command not found`。
   可靠套路：① 本地写 `.sh`，`ssh host 'cat > /tmp/x.sh' < 本地文件` 上传；② `docker cp /tmp/x.sh <容器>:/tmp/`；③ `docker exec <容器> bash /tmp/x.sh`。命令里**一个引号都不出现**。
3. **不要用 stdin 把 heredoc 喂给容器**（`ssh host docker exec -i c bash -s <<EOF`）：外层 bash 已把同一 stdin 读走，`docker exec -i` 抢不到，报错像随机故障。
