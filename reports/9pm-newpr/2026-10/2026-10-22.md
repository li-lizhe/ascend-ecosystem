## 四、缺陷与修法（一句话）

`custom_hf_download()` 仍按 huggingface_hub < 1.0 的写法下载模型：
① 传了 1.0 已删除的 `resume_download=True` / `local_dir_use_symlinks=use_symlinks`（现在被兼容层接收后忽略 ⇒ **每次下载打两条 UserWarning**）；
② `USE_SYMLINKS: true` 是**静默空转**——代码探测软链、打印「Using symlinks to download models…（并让你别清 cache）」，
   然后 huggingface_hub 根本不建软链（实测下来的文件 `islink=False, st_nlink=1`，而 `<cache_dir>` 压根不存在）；
③ 结尾仍执行 `shutil.rmtree(<cache_dir>/ckpts)`，而该目录在新版 hub 下永不创建 ⇒ **每次成功下载都打一行 `[WinError 3] 系统找不到指定的路径`**（用户 #478 报的就是这行）。

修法：保留函数签名（调用方零改动），去掉两个已废参数、`USE_SYMLINKS` 改为显式警告、
删掉结尾的 cache 清理与随之作废的 `contextlib.suppress` / `huggingface_hub.constants` 导入，
`dsine/__init__.py` 同样去掉 `local_dir_use_symlinks=False`。`cache_dir`/`local_dir`/`subfolder`/`etag_timeout`/`repo_type` 全部保持原样，
**ckpts 目录落盘结构不变**。

### 6.1 issue #638 正文（English，实际发出的即下方全文）

```markdown
### What happens

`custom_hf_download()` in `src/custom_controlnet_aux/util.py` still uses the
huggingface_hub < 1.0 way of downloading into a local folder. Three things come out of
that on current huggingface_hub (2.2.0 here):

1. `hf_hub_download()` is called with `resume_download=True` and
   `local_dir_use_symlinks=use_symlinks`. Both arguments were removed in
   huggingface_hub 1.0; the compatibility validator only warns and ignores them, so
   every download logs two `UserWarning`s.
2. `USE_SYMLINKS: true` in config.yaml is a silent no-op. The code probes symlink
   support, prints *"Using symlinks to download models. ... And do not purge the cache
   folder after downloading"*, and then no symlink is created: with `local_dir` set,
   huggingface_hub writes a real file into the ckpts folder and nothing into
   `cache_dir`.
3. The download ends with an error line, because the function still runs
   `shutil.rmtree(os.path.join(cache_dir, "ckpts"))` on a directory that
   huggingface_hub 1.0+ never creates:

       [WinError 3] 系统找不到指定的路径。: '<custom_temp_path>\ckpts'

   This line shows up in user reports such as #478.

### Verified locally

huggingface_hub 2.2.0, Windows, calling the real function with a small hub file
(`hf-internal-testing/tiny-random-bert/config.json`, torch/cv2 stubbed since only the
download path is exercised):

```
# before, USE_SYMLINKS=false
.../huggingface_hub/utils/_validators.py:189: UserWarning: The `resume_download` argument is deprecated and ignored in `hf_hub_download`. ...
.../huggingface_hub/utils/_validators.py:205: UserWarning: The `local_dir_use_symlinks` argument is deprecated and ignored in `hf_hub_download`. ...
[WinError 3] 系统找不到指定的路径。: '.../verify/before_false\cache\ckpts'
model_path is .../before_false/ckpts/hf-internal-testing/tiny-random-bert/config.json
file exists: True size 548

# before, USE_SYMLINKS=true
Using symlinks to download models.
 Make sure you have enough space on your cache folder.
 ...
-> downloaded file: os.path.islink=False, st_nlink=1   # real file, no symlink
-> <cache_dir> exists: False                            # the cache the message tells you to keep
```

### Proposed fix

Keep the signature of `custom_hf_download()` (callers unaffected) and:

* drop the two removed arguments;
* warn explicitly when `USE_SYMLINKS` is enabled instead of pretending to honour it;
* drop the trailing `shutil.rmtree` (plus the now unused `contextlib.suppress` /
  `huggingface_hub.constants` imports);
* do the same one-line cleanup in `src/custom_controlnet_aux/dsine/__init__.py`, which
  passes `local_dir_use_symlinks=False`.

`hf_hub_download()` keeps `cache_dir` / `local_dir` / `subfolder` / `etag_timeout` /
`repo_type` exactly as today, so the on-disk layout of the ckpts folder does not change.

### Note

This does not change the failure modes reported in #478 / #570 (those are about
downloads not completing at all); it only removes the deprecated arguments and the
misleading log output from the download path.

```

### 6.2 PR #639 正文（English，实际发出的即下方全文）

```markdown
## What

`custom_hf_download()` (and the small copy in `src/custom_controlnet_aux/dsine/__init__.py`)
is still written against huggingface_hub < 1.0:

* it passes `resume_download=True` and `local_dir_use_symlinks=use_symlinks` to
  `hf_hub_download()`. Both arguments were removed in huggingface_hub 1.0 (the
  compatibility validator accepts them and ignores them), so every download logs two
  `UserWarning`s;
* because `local_dir` now receives a real file and huggingface_hub does not create
  `<cache_dir>/ckpts` any more, the trailing
  `shutil.rmtree(os.path.join(cache_dir, "ckpts"))` always fails and is printed:

      [WinError 3] 系统找不到指定的路径。: '<custom_temp_path>\ckpts'

This PR:

* drops the two removed arguments and keeps `cache_dir` / `local_dir` / `subfolder` /
  `etag_timeout` / `repo_type` untouched, so the on-disk layout of the ckpts folder is
  the same as before;
* keeps the signature of `custom_hf_download()` unchanged (no caller edits) and warns
  explicitly when `USE_SYMLINKS` is enabled, instead of probing symlinks, printing
  *"Using symlinks to download models"* and then letting huggingface_hub ignore the
  option (no symlink is created);
* removes the stale cache cleanup and the now unused `contextlib.suppress` /
  `huggingface_hub.constants` imports;
* removes `local_dir_use_symlinks=False` in `src/custom_controlnet_aux/dsine/__init__.py`.

Fixes #638

## Verification

huggingface_hub 2.2.0 (latest release) on Windows, calling the real function on the real
file (`hf-internal-testing/tiny-random-bert/config.json`); `torch` and `cv2` are stubbed
because only the download path is exercised:
```
