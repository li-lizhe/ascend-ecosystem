## 四、缺陷与修法

上游（`inference/core/env.py:1209`）：

```python
DEVICE = os.getenv("DEVICE")
```

配合 19 处复制品（`inference/models/{smolvlm,owlv2,trocr,doctr,easy_ocr,perception_encoder,transformers,moondream2}/…`、
`sam/segment_anything.py`、`sam2|sam3/*` 等）：

```python
if DEVICE is None:
    DEVICE = "cuda:0" if torch.cuda.is_available() else "cpu"
```

后果：非 `torch.cuda` 暴露的加速器（昇腾 NPU、Intel XPU、MLU、GCU、MUSA）上，模型**静默加载到 CPU**。

修法（最小侵入：只改**唯一一处来源**，19 处复制品随之失效，无 `if npu:` 分支）：

```python
def _resolve_default_device() -> Optional[str]:
    try:
        import torch
    except ImportError:
        return None          # torch 可选：保持 env 在无 torch 环境可 import
    accelerator = getattr(torch, "accelerator", None)
    if accelerator is not None:
        try:
            device = accelerator.current_accelerator(check_available=True)
        except Exception:
            device = None
        if device is not None:
            return "cuda:0" if device.type == "cuda" else device.type
    if torch.cuda.is_available():      # torch < 2.5 的退路，保持原字符串
        return "cuda:0"
    return "cpu"

DEVICE = os.getenv("DEVICE")
if DEVICE is None:
    DEVICE = _resolve_default_device()
```

刻意**不用** `"cuda" if torch.cuda.is_available() else "cpu"`（那会让昇腾用户退回 CPU）。

### 6.1 issue 正文（自建，English）

标题：`DEVICE autodetect is CUDA-only: models load on CPU on non-CUDA accelerators (Ascend NPU, XPU)`

```markdown
### Summary

When `DEVICE` is not set, the default device is decided by a CUDA-only fallback that is repeated in
every model module, while `inference/core/env.py` itself only reads the environment:

    # inference/core/env.py
    DEVICE = os.getenv("DEVICE")

    # repeated in ~19 model modules, e.g. inference/models/smolvlm/smolvlm.py:11
    if DEVICE is None:
        DEVICE = "cuda:0" if torch.cuda.is_available() else "cpu"

`torch.cuda.is_available()` is False on every accelerator that is not exposed through `torch.cuda`
(Ascend NPU, Intel XPU, MLU, GCU, MUSA) even when the accelerator is present and
`torch.accelerator.current_accelerator()` reports it. `DEVICE` therefore becomes `"cpu"` and every
model (smolvlm, owlv2, trocr, doctr, easy_ocr, perception_encoder, transformers, moondream2, the
sam/sam2/sam3 wrappers, ...) is loaded and executed on the CPU, without any warning.

### Evidence (Ascend 910B4, real hardware)

torch 2.15.0.dev20260917+cpu + torch_npu 2.15.0.dev20260917+gitec69335, 8 x Ascend910B4:

    cuda.is_available : False
    npu.is_available  : True | npu.device_count: 8
    torch.accelerator : True | current_accelerator -> npu
    BEFORE (upstream)  : cpu
    AFTER  (proposed)  : npu
    real tensor op on npu -> 15 | tensor device: npu:0

### Proposed fix

Resolve the default once, in `inference/core/env.py`, through `torch.accelerator` (PyTorch >= 2.5),
keeping `torch.cuda` as the fallback for older builds and returning `None` when torch is absent (so
`import inference.core.env` keeps working without torch). With `DEVICE` already resolved, the
`if DEVICE is None:` copies in the model modules become dead code. A PR that does this is on its way.
```

## 十一、流程与踩坑（本轮新经验）

1. **★ GitHub Search API 的二级限流（secondary rate limit）很凶**：连续十几次 search（issues/code）后会整体
   返回 `You have exceeded a secondary rate limit`，而 `/rate_limit` 仍显示 `search.remaining>0`。
   应对：检索批量脚本要 `sleep(1~2)`，并把「按仓拉 open issue 列表」（core API，5000/h）作为主筛手段，
   search 只用于 code search 定位。
2. **★ GitHub fork 重名**：`POST /repos/{upstream}/forks` 不带 `name` 时，若账号下已有同名 fork（哪怕是
   别的上游的 fork，如 `li-lizhe/inference`=xorbitsai 的 fork），会直接失败/不可预期。显式 `{"name": "..."}`
   最稳。
3. **「活仓」不等于「有料」**：smolagents/lighteval/Mooncake 都极活跃，但都有审计型贡献者**当天
   issue→PR 成对**提交，浅层 bug 一小时内被认领。选仓要看**竞争面**，不只看 merge 速度。
4. **本轮靠「同类复制品计数」找系统性缺陷**：`code search "cuda.is_available() else \"cpu\""` 一次列出
   29 个文件 ⇒ 用「同一表达式出现在 N 个文件」当作系统性缺陷的信号，比逐个文件读代码高效得多。
5. 真机探针复用 `npu_channel.py --exec "docker exec npu-lizhe …"` + base64 传脚本（169 的 `npu-lizhe`
   已带完整 torch_npu，8×910B4；`/opt/miniconda/envs/npu/bin/python`）。
