## ① X-GenGroup/Flow-Factory — PR #244（🔴 真机验证）

- 标题：`[utils,trainers,test] fix: restore accelerator RNG state on non-CUDA accelerators`
- Issue（自建）：#243 · 分支 `fix/accelerator-rng-state` · base `main`（base sha `5dfb5e89d201`）
- diff：3 文件 +90/−13（`utils/base.py` +31/−8、`distillation_runtime.py` +5/−5、`tests/test_accelerator_rng.py` +54）
- 行尾：三个 blob 推送后 API 回读 `\r\n` 计数均为 0（LF 合规）
- mergeable_state：`clean`；CI：无 check-run、无 CLA bot 评论（该仓对 fork PR 无自动 CI）

**问题**：`isolated_rng()` 与 `_preserve_rollout_cursor_rng()` 用 `torch.cuda.is_available()` 判定是否快照
加速器 RNG 状态 ⇒ NPU 上快照被跳过，但 `torch.manual_seed()` 是设备无关的（同样推进 NPU 生成器）
⇒ 块内 NPU RNG 状态泄漏到块外，seeded 段之后的噪声采样不再延续块前序列（可复现性破坏）。CUDA 上正常，故一直未暴露。

**修复**：`accelerator_rng_module()` 经 `torch.accelerator.current_accelerator().type` 解析出
`torch.cuda`/`torch.npu`/`torch.xpu`，两处调用点共用；仍在加速器上执行（无 CUDA→CPU fallback）。torch>=2.10 已 pin。

**真机证据（函数源码 by `ast` 逐字节取自 before/after 文件后 exec）**：

```

     expected next npu draw: [0.35369113087654114, 0.6635878086090088, -0.9774994254112244, 0.7763612866401672]
     actual   next npu draw: [-0.3343716561794281, -0.5942094922065735, 0.808901846408844, -0.5996915102005005]
[before] _preserve_rollout_cursor_rng: npu stream preserved = False
[after]  isolated_rng(999): npu stream preserved after exit = True

```

块内那次抽样 before/after 完全相同 ⇒ seeded 段本身未变，变的是块后的状态恢复（设备确实选到 npu，没退回 CPU）。
PR 内新测试文件在真机原样跑通：`3 passed in 10.05s`。

**问题**：`BaseRecLabelDecode.get_word_info()` 用 ASCII 类 `[a-zA-Z0-9]` 判字符类型；`ö/ä/ü/é` 不匹配 ⇒
落入 `symbol` 分支，而 c_state 变化会切断当前词分组 ⇒ `return_word_box=True` 时 `Köln` → `["K","ö","ln"]`，词框坐标也算错。

**修复**：改为 `re.search(r"[\w]", char, re.UNICODE) and char != "_"`（PaddleOCR #17201 的 Unicode 部分移植）。
`_` 显式排除 ⇒ `hello_world` 分组不变（与 `pred_reverse()` 口径一致）。
