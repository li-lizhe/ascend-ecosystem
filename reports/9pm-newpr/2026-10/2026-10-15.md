### 问题（真 crash bug，非设备硬编码）

`LMCacheConnectorV1Impl.request_finished()` 在 `kv_transfer_params` 含 `ret_first_tok`
（PD 分离 prefill 路径）时无条件取 `request._output_token_ids[0]`：

```python
if params is not None and "ret_first_tok" in params:
    return_params = {"first_tok": request._output_token_ids[0], }
```

请求在产出第一个 output token **之前**被 abort（客户端在 prefill 阶段挂断、引擎侧 abort/evict）
时该 list 为空 ⇒ `IndexError` 从 connector 逃逸进 EngineCore ⇒ 实例 `EngineDeadError`
（报告方 5/5 复现，1P1D 部署）。失败路径纯 Python，与传输通道（NIXL/UCX）无关。

### 修复

只在 `ret_first_tok` 分支加保护：无 output token 时 `logger.warning(...)` 并**不返回
`first_tok`**，而非抛异常。有 token 的请求行为逐位不变（含 first token id = `0`，
单列一条测试）。选「不返回」而非返回 `None`，因为消费端
`examples/disagg_prefill/disagg_proxy_server.py` 是 `...["first_tok"]` 直取，喂 `None`
反而会把 `None` 塞进 prompt。

### 验证（🟡 本地；失败路径纯 Python，无需 GPU/NPU 或引擎）

用 `ast` 从 before/after 源文件**逐字节提取**真实 `request_finished`，在 stub 命名空间
（`RequestStatus` / `logger` / 绕过 `__init__` 的 connector 属性，与仓库既有测试同形）中 exec：

```
== BEFORE ==
   [RAISE] aborted, no output token, ret_first_tok -> IndexError: list index out of range
   [ok]    finished, one output token              -> delay_free=False return_params={'first_tok': 42}
   [ok]    finished, first token id == 0           -> delay_free=False return_params={'first_tok': 0}
== AFTER ==
   [ok]    aborted, no output token, ret_first_tok -> delay_free=False return_params=None
           warning: "Skipping first-token return for request req-aborted: the request finished before producing any output token."
   [ok]    finished, one output token              -> delay_free=False return_params={'first_tok': 42}
   [ok]    finished, first token id == 0           -> delay_free=False return_params={'first_tok': 0}
```

新增 4 条回归测试（Scheduler 路径 abort / 引擎已初始化路径 abort 且 cleanup 仍执行 / 正常路径 /
token id = 0）追加进仓库**既有**测试文件，沿用其 `_make_connector` / `_capture_adapter_warnings`
夹具；两份文件 `py_compile` 通过。
**未执行**：`pytest tests/v1/...`（该模块 `pytest.importorskip("vllm")`，本机无 vLLM 安装）⇒
